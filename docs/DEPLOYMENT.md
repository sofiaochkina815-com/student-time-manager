# Публикация Django и PostgreSQL

Подготовлен render.yaml: бесплатный Python Web Service, отдельный PostgreSQL, Gunicorn, WhiteNoise, миграции при старте и health/readiness. Личные файлы сохраняются в PostgreSQL, а не на временном диске. SECRET_KEY генерирует платформа; DEBUG=0 требует DATABASE_URL. Доверие X-Forwarded-Proto включать только за прокси, который сам задаёт этот заголовок.

Для фактической публикации нужен доступ к аккаунту Render: New → Blueprint → выбрать этот репозиторий → проверить Free у web и database → Apply. Связанные инструменты текущей сессии не предоставляют управление Render. Созданный конфигурационный файл не означает, что приложение уже размещено.

После размещения проверить HTTPS, /health/ready/, CSS, регистрацию и отдельные входы, файлы после перезапуска и отозванный доступ. Администратора можно создать с локального компьютера командой main.py createsuperuser, подключившись к размещённой БД через её внешний DATABASE_URL. Пароль вводится в интерактивном запросе; предустановленного пароля в коде нет. Наличие Shell на бесплатном тарифе не предполагается.

Согласно документации Render, проверенной 22.11.2026, бесплатный сервис засыпает после простоя, диск эфемерный, бесплатная PostgreSQL действует 30 дней. Срок базы нужно записать после создания и до истечения сохранить собственную резервную копию. Квоты аккаунта проверяются перед запуском; переход на платный тариф не разрешён.

Источники: https://render.com/docs/free ; https://render.com/docs/deploy-django ; https://whitenoise.readthedocs.io/en/stable/django.html .
