# PostgreSQL

При DEBUG=0 обязателен DATABASE_URL PostgreSQL. TLS-параметры sslmode и channel_binding сохраняются; неизвестные и повторяющиеся параметры отклоняются. Пример без пароля: `postgresql://USER@HOST:5432/DB?sslmode=require&connect_timeout=5`. Настоящий URL хранится в переменных окружения.

Миграции: `.venv/bin/python main.py migrate --noinput`. Проверки: `.venv/bin/python main.py test planner`. В SQLite проверка реальной блокировки пропускается; на PostgreSQL два одновременных ввода по 1000 минут должны дать одну запись и один отказ по суточному лимиту.

Источник: https://docs.djangoproject.com/en/6.1/ref/databases/ . Испытание выполнялось на отдельной локальной базе.

## Личные файлы в базе данных

Чтобы хранить вложения вместе с локальной БД, установите PRIVATE_FILE_STORAGE=database: содержимое приватных вложений хранится в PostgreSQL и выдаётся прежним маршрутом с проверкой владельца. Публичного MEDIA_URL нет. Служебная таблица PrivateFileBlob не является новой предметной сущностью.

Если уже есть локальные файлы, сначала перенесите БД и каталог .local/private-files в доступную среду, выполните `main.py copy_private_files_to_database`, проверьте скачивание и только затем откажитесь от локальных копий. Команда сравнивает размер/SHA-256 и не удаляет исходники. Простое переключение переменной само по себе старые файлы не переносит.
